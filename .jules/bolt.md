## 2024-06-29 - [Data Races with Sequential File Writes on `@MainActor`]
**Learning:** Offloading synchronous file I/O operations from an `@MainActor` class (e.g., `HistoryManager`, `PresetManager`) to prevent UI blocking requires care. Using `Task.detached` is an anti-pattern for sequential file writes because multiple detached tasks can run concurrently and interleave, leading to data races (e.g., saving an older state over a newer one). Capturing `self` inside `Task.detached` from a `@MainActor` also introduces strict concurrency violations.
**Action:** Always use a dedicated serial `DispatchQueue` (e.g., `ioQueue.async`) for sequential I/O operations from a `@MainActor`. Synchronously capture all required state (such as the data to save and the file path) as local variables on the main thread *before* dispatching to the background queue, ensuring both correct execution order and thread safety.

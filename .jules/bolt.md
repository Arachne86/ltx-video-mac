## 2024-06-24 - O(N^2) String Parsing in Swift Subprocess Outputs
**Learning:** In `LTXBridge.swift`, accumulating continuous subprocess `stderr` outputs and repeatedly parsing the entire accumulated string with `components(separatedBy: "\n")` on every read chunk causes O(N^2) time complexity. For large MLX generation logs, this causes severe main thread blocking and UI hitches because progress handlers block waiting for parsed chunks.
**Action:** Use a local `lineBuffer` inside the `readabilityHandler` to find newline indices (`firstIndex(of: "\n")`), slice the buffer to extract complete lines, and remove the yielded lines from the buffer. Yield only complete lines to the handler block to achieve O(N) linear time processing and maintain UI responsiveness. For static multi-line outputs like `runPythonSync`, prefer `enumerateLines { line, stop in }` instead of `.components(separatedBy: "\n")` to avoid generating intermediate arrays in memory.

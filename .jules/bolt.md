## 2024-03-20 - Offloading Synchronous Disk I/O in @MainActor Classes
**Learning:** In `@MainActor` Swift classes (like `HistoryManager` and `PresetManager`), performing synchronous file system operations (e.g., `try JSONEncoder().encode()` followed by `try data.write()`, or `FileManager.default.removeItem()`) directly inside methods blocks the main thread, causing severe UI hitches and jank. Offloading this work to a background context is required. However, using `Task.detached` for sequential file writes is an anti-pattern as it executes concurrently, potentially introducing data races and out-of-order writes. Furthermore, strictly capturing `self` inside an async closure within a main-actor bound context can trigger strict concurrency warnings/errors.
**Action:** When offloading synchronous disk I/O in UI-bound classes, create a dedicated serial background `DispatchQueue` (e.g., `private let ioQueue = DispatchQueue(label: "com.app.ioQueue")`) to ensure sequential execution. Always capture required state synchronously as local variables on the main thread *before* dispatching to the background queue (e.g., `let stateToSave = self.results`), avoiding concurrent mutations or `self` captures inside the async block.
